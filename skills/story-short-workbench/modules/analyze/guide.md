# 短篇分析适配

这是整合时为短篇导入补齐的本地适配，依据写作模块已有的 [输出契约](../write/references/output-contract.md) 和导入映射执行，不需要原 `story-short-analyze`。

## 输入、复用与证据

用户给定参考文本/文件或由导入记录传入来源、范围、书名、题材。完整读取本次范围，保留段号或物理行号。原文只读，原样备份到 `拆文库/{书名}/原文/`；记录源文件相对路径与SHA-256。长稿分连续块落盘事实，不把局部阅读说成完整分析。

已有 `_meta.json` 时核对源文校验值、实际文件与完成阶段；同源完整成果直接复用，中断从未完成阶段继续。来源变化或重拆要求时保留旧成果、使用新目录或先归档，不静默覆盖。自己导入的小说只作为续写基线，不当外部对标。

## 按阶段产出

在 `_meta.json` 中按输出契约记录 `version: "2.0"`、真实字数、非空 `genre_detected`、创建时间、完成阶段和当前进行阶段；新增 `source_sha256`、`analysis_scope`、`source_complete` 说明证据范围。题材未知写通用，不编造精确分类。字数口径明确，续跑沿用同一口径。

1. Stage 2：提取故事核、功能结构、梗概，写 `拆文报告.md` 和 `情节节点.md`。每个节点含来源位置、事件、目标/阻碍、行动→结果→后果、信息差与人物/关系变化。按真实语义切分，不为计数制造节点。
2. Stage 3：在报告补情感曲线与爆点/期待路径，覆盖实际发生的铺垫、升温、峰值、释放，缺结尾的残稿明确缺失，不补成已发生。
3. Stage 4：分析反转与铺垫，在报告给原文证据，另写 `写作手法.md`，说明开头、视角、叙事距离、信息控制、场景/对白、句段节奏和结尾中实际存在的手法。无反转作品填「无反转」，不硬凑三条线索。
4. Stage 5：报告补人物目标/动机/关系、开头与结尾功能、因果与首尾呼应。未知真相、未写结局标为未知。
5. Stage 6：综合五维质量、共鸣与可借鉴结构，标出不宜模仿及证据不足项；`structure_counts` 从已经写出的分析机械计数，不用推测值或最低值填充。

报告至少包含故事核与题材、功能结构、梗概、人物、情感线/爆点、反转、首尾、综合评估和待补项，让导入模块可反推设定与小节大纲。

## 完成与残稿

完整参考短篇按输出契约的字段与阈值验收，验收前不能登记Stage 6完成。计数不足先判断是否漏读或漏分析；原文确实不足就如实记录，不能补写原文或杜撰证据通过门槛。

导入残稿时交付已写部分的真实分析。与未写结尾相关的阈值不适用，记录 `source_complete: false`、`analysis_scope: "existing-draft"`、实际未完成项及 `import_ready`。本次可迁移的标准是源文完整备份、已写范围节点可核对、续写基线与待补项清楚；`import_ready` 不冒充全篇 Stage 6验收。迁移后未定内容仍待作者决定。

只分析用户指定片段时报告只对应片段，不将其标为整篇完成。分析后按作者请求交付报告或交还导入模块，不自动创作另一篇。
