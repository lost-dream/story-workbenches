# 短篇小说工作台

围绕一篇短篇的目标情绪，完成构思、小节大纲、正文与精修，也可从导入或审稿进入。无需长篇工程或未安装的短篇扫榜、拆文技能。

## 执行约定

- 只加载下表命中的模块及它列出的当前阶段资料，不预读整套资料。模块的 `guide.md` 是流程说明，不是另一个需要安装的 skill。
- `modules/...` 从本 SKILL.md 所在目录解析；模块文档中的 `references/...`、`scripts/...` 和 `{skill 根}` 从该模块目录解析。跨模块旧名称路径已转成 `modules/...`，不要搜索或调用原来的八个 skill。运行命令时使用脚本绝对路径与项目绝对路径，故事产物写入作者项目，不写进技能目录。
- 默认由当前会话直接执行。分析按连续章节块串行处理；审查默认 solo。无需 `.story-deployed`、自定义 agent 或额外 setup skill。仅用户明确要求多助手且当前工具支持时，才按模块的可选委派说明执行；缺少助手直接继续，不能让作者先安装环境。旧部署版本只作兼容信息，不作内容工作前置。
- 当前请求决定对象、范围、字数、人称和停点。只讨论或只做大纲就交付该层级；已经明确授权的阶段连续完成，不因模板中的通用询问重新索要同一授权。真正缺少会改变结果的信息或遇到作者尚未决定的剧情分歧时，才集中询问。
- 原文、项目设定、已确认剧情与本书文风优先；不编造榜单、正文证据、平台规则或已完成进度。参考作品与本书续写基线分开，导入自己的书不会自动变成对标书。
- 写作、改稿前按模块加载文风裁决；只检测、只审查不改正文。需要去味时才进入去味模块，不为完成一条请求自动扫榜、拆整本、润色或生成封面。
- 生图/改图先使用用户本任务已指定的方式；未指定时先询问「Image2 API 还是内置 image_gen 模型」。同一任务/批次沿用选择，不自行切换或设置备用通路。只写封面方案或提示词无需生图。
- 联网采集、图片工具和 Python/Node 按所选操作使用。实时市场信息、平台尺寸与上传规则在实际需要时核对来源和日期；历史参考不能冒充现行规则。浏览器采集能力缺失时，使用当前可用的网页工具或用户提供的数据，说明样本限制。
- 已有项目先读当前书、落盘进度及源文件，再续接缺失步骤。原文备份与已有有效成果保留；不用旧对话记忆替代文件。除非用户要求，不自动向 GitHub 或小说平台发布。

## 按需求进入

| 当前需求 | 先完整读取 | 关键交付与停点 |
|---|---|---|
| 短篇构思、人物与反转、只要大纲 | [短篇写作流程](modules/write/guide.md) | 目标情绪、`设定.md`、`小节大纲.md`；只规划不展开正文 |
| 写短篇、盐言故事、按已定稿大纲写正文 | [短篇写作流程](modules/write/guide.md) | 通过设计验收后按授权写作；保留小节完整性与锁定字数 |
| 精修、修改指定小节、短篇续写 | [短篇写作流程](modules/write/guide.md) | 只处理指定内容，不自动扩大重写范围 |
| 导入自己的短篇、继续导入 | [导入流程](modules/import/guide.md) | 原文备份、分析资产与三文件短篇工程 |
| 分析参考短篇、导入所需分析 | [短篇分析适配](modules/analyze/guide.md) | 情节节点、情感反转、写作手法和来源位置；按实际范围说明完成度 |
| 去AI味、润色、仅检测 | [去味流程](modules/deslop/guide.md) | 保留短篇叙述声线、主观判断及有功能的钩子；检测不改稿 |
| 审稿、自检、检查逻辑和反转 | [审查流程](modules/review/guide.md) | 按平台标准出有原文证据的报告，不改正文 |
| 小说封面、封面提示词、改封面 | [封面流程](modules/cover/guide.md) | 书名、笔名、构图与文字安全区；实际生图先落实方式 |

## 短篇交接

工程以 `{标题}/设定.md`、`小节大纲.md`、`正文.md` 三个单文件为核心，可另有 `.story/work/` 和明确选择的外部对标引用；不建长篇的 `追踪/`、`大纲/` 或 `正文/` 多章目录。

当前请求已说清目标情绪、题材、人称和字数时直接采用，不重复选择。仅给题材而情绪会改变方案时提供具体候选。用户只要求构思就停在设计；已明确要求从构思写到成稿时完成必要设计后连续写完。默认字数只在用户未指定时使用，不能覆盖短于默认范围的明确要求。

本包没有新增短篇平台榜单采集能力。用户要实时短篇市场研究时，按其范围用可用网页工具获取真实样本或使用其提供的数据；不能拿长篇榜单代替短篇市场结论。

裸调用时列出构思、写正文、导入、去味、审稿、封面等阶段，不自动写整篇。项目明确为长篇时说明 `story-long-workbench` 的适用性，不把自己的短篇导入结果登记为外部对标。

## 来源与兼容

短篇写作、导入、去味、审查和封面的原始专项资源随包提供。短篇分析适配根据这八个源技能中既有的导入映射和短篇输出契约补齐，不宣称安装了原 `story-short-analyze`。来源与文件校验值见 [来源清单](references/sources.json)。
