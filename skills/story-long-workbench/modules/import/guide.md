# 旧稿导入为可续写工程

导入目标是保留作者已有内容，重建可继续写作的项目。仅要分析时进入本包分析模块，不建立写作工程。

## Phase 1：来源、范围与记录

先读用户指定源文件或已有导入记录，判断书名、章节/小节、字数、题材、平台、完结状态与末章残稿情况；篇幅判定详见 [篇幅路由](references/length-routing.md)，用户明确声明优先。当前工作台已明确且源文结构相符时不重复选择。

信息已给定则直接采用；有篇幅冲突、末章残稿处理或来源范围不清时，只补问这些实质问题。外部对标可选，不主动强制绑定，自己的导入书绝不能登记为自己的对标书。默认当前会话串行，无需 setup 或 agent 安装。

在 `{书目录}/.story/work/导入记录.md` 记录原文路径、源文件校验值、篇幅、范围、题材、平台、完结/残稿决定、外部对标（没有写未绑定）、作者约束和下列进度。用户粘贴原文则先原样保存到同目录的 `导入原文.md`；源文件由分析模块原样备份。

- 深度分析及实际覆盖范围。
- 结构迁移与卷划分（长篇）。
- 细纲验收到哪章（长篇）。
- 追踪初始化与检查（长篇）。
- 核对、汇报与激活。

## Phase 2：分析资产

读取 [导入分析交接](references/deep-analysis.md)，进入本包 `modules/analyze/guide.md`。长篇复用索引、连续批次、状态与现有分析的增强规则；短篇用本包适配流程产生 `拆文报告.md`、`情节节点.md`、`写作手法.md` 和 `_meta.json`。

导入已授权的分析范围自动完成，不在前三章停靠再次询问。已有成果能验证且足以迁移时直接复用，只补缺失项；不能以旧 schema 或缺新增字段为由重拆全书。超过200章按 [特殊情况](references/import-special-cases.md) 约定实际首期分析范围，报告不能把未深拆章节称作已深拆。

## Phase 3：结构迁移

- 长篇完整读取 [长篇映射](references/structure-mapping-long.md) 与当前步骤要求的资料，生成设定、大纲、正文。原文有卷界时沿用；没有卷界且选择会改变工程时，先给出分卷建议让作者决定。逐批反推细纲执行 [细纲反推](references/outline-reverse.md)，使用模块内脚本验收。
- 短篇完整读取 [短篇映射](references/structure-mapping-short.md)，生成 `设定.md`、`小节大纲.md`、`正文.md`。不产长篇目录和追踪，不把自己的分析源复制进 `对标/`。

迁移只做获准的格式规范化，不改写正文情节；事实不明写待补充，不能编造反转、设定或伏笔。已存在的作者文件先核对，避免覆盖手工修订。

## Phase 4：追踪（仅长篇）

完整读取 [导入追踪](references/import-tracking.md) 及初始化规则，使用 `scripts/tracking_commit.py init` 与 `check`。权威状态与派生视图由事务脚本生成，不手改。短篇跳过。

## Phase 5：汇报与激活

按 [汇报自检](references/import-report.md) 核对实际产物、范围、缺失/待决定项和续写入口，更新导入记录及 `.active-book`，只对真实完成的步骤打勾。导入结束不自动开始续写或生成封面。

## 时刻表与交接

每个阶段开始读落盘导入记录，从第一个未完成步骤续接；结束写回新决定、证据范围和进度。需要新上下文时可以建议换对话，用户要求继续就在当前对话继续，不为换对话强行停工。源文改变或旧产物不匹配时保留旧产物与原始备份，说明差异后选择新分析目录或由作者决定替换范围。
